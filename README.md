# Online Shop (Backend)

Backend для интернет-магазина музыкальных пластинок, построенный на микросервисной архитектуре.

Приложение разделено на независимые сервисы для работы с пользователями, каталогом товаров и заказами. Сервисы используют отдельные базы данных и обмениваются событиями через RabbitMQ.

## Возможности

* регистрация пользователей;
* авторизация с использованием JWT;
* разграничение прав пользователей и администраторов;
* просмотр каталога музыкальных пластинок;
* добавление новых товаров администратором;
* редактирование информации о товарах;
* удаление товаров;
* работа с жанрами;
* добавление товаров в корзину;
* изменение содержимого корзины;
* создание заказов;
* расчет итоговой стоимости заказа;
* синхронизация данных каталога между сервисами через RabbitMQ;
* логирование основных операций приложения.

## Архитектура

Проект разделен на три микросервиса:

### Users Service

Отвечает за работу с пользователями:

* регистрацию;
* авторизацию;
* хранение данных пользователей;
* проверку JWT-токенов;
* роли пользователей.

### Catalog Service

Отвечает за каталог товаров:

* получение списка пластинок;
* хранение информации об альбомах, исполнителях, цене и наличии;
* работу с жанрами;
* создание товаров;
* редактирование товаров;
* удаление товаров.

Операции изменения каталога доступны только пользователям с ролью администратора.

После изменения каталога сервис отправляет событие в RabbitMQ, чтобы остальные сервисы могли синхронизировать свои локальные данные.

### Orders Service

Отвечает за пользовательские покупки:

* добавление товаров в корзину;
* хранение корзины пользователя;
* создание заказа;
* расчет стоимости заказа;
* хранение информации о заказах.

Orders Service также получает сообщения об изменениях каталога через RabbitMQ и обновляет локальные данные о товарах.

## Основные сущности

### User

Пользователь системы.

Содержит:

* username;
* email;
* password hash;
* role.

Пароли хранятся в хэшированном виде.

### Record

Музыкальная пластинка.

Содержит:

* название альбома;
* исполнителя;
* цену;
* количество товара в наличии;
* жанры.

### Cart

Корзина пользователя.

Связывает пользователя с выбранными товарами и хранит их количество.

### Order

Заказ пользователя.

Содержит список выбранных товаров, дату заказа и итоговую стоимость.

## Авторизация

После успешного входа пользователь получает JWT access token.

Токен передается при обращении к защищенным endpoint'ам:

```text
Authorization: Bearer <token>
```

В JWT также хранится роль пользователя.

Для операций управления каталогом выполняется дополнительная проверка роли:

```text
role = admin
```

Таким образом обычный пользователь может просматривать каталог и оформлять заказы, а изменение товаров доступно администратору.

## REST API

### Users Service

```http
POST /signup
```

Регистрация нового пользователя.

```http
POST /login
```

Авторизация и получение JWT-токена.

### Catalog Service

```http
GET /catalog
```

Получение каталога товаров.

```http
POST /create_record
```

Добавление новой пластинки. Требуются права администратора.

```http
PUT /catalog/{record_id}
```

Изменение информации о товаре.

```http
DELETE /delete_record/{record_id}
```

Удаление товара из каталога.

### Orders Service

```http
POST /cart
```

Добавление товара в корзину пользователя.

```http
GET /order
```

Создание заказа на основе содержимого корзины.

При создании заказа рассчитывается общая стоимость товаров, после чего корзина пользователя очищается.

## Взаимодействие сервисов

Catalog Service публикует события в очередь RabbitMQ:

```text
catalog_updates
```

События создаются при:

* добавлении товара;
* изменении товара;
* удалении товара.

Orders Service получает сообщения из очереди и синхронизирует локальные данные каталога.

Пример структуры сообщения:

```json
{
  "action": "update",
  "id": 1,
  "album_name": "OK Computer",
  "band_name": "Radiohead",
  "price": 6000,
  "in_stock": 15
}
```

Такой подход позволяет сервисам взаимодействовать асинхронно и уменьшает связанность между отдельными частями приложения.

## База данных

Для хранения данных используется PostgreSQL.

Работа с базой реализована через асинхронный SQLAlchemy:

```python
create_async_engine(...)
```

Каждый сервис использует собственное подключение к базе данных, что соответствует разделению ответственности между микросервисами.

## Что реализовано в проекте

В рамках проекта была реализована backend-архитектура интернет-магазина с разделением ответственности между сервисами, асинхронной работой с PostgreSQL, JWT-аутентификацией, ролевой моделью доступа и событийным взаимодействием через RabbitMQ.
